# ARARE AI 電話予約品質改善プロンプト

ARARE AIの電話予約受付を、実通話録音・Twilio履歴・DB履歴・Renderログ・画面表示を根拠に改善する。

## 完了条件

- 電話回線とSMSはTwilioを継続し、会話理解と予約判断にはOpenAI/GPTを利用する。
- 音声出力は方式名ではなく、実電話で日本語ネイティブの落ち着いた男性受付として自然かつ明瞭であることを基準に選ぶ。
- 「はい大丈夫です」「今のでいい」「了解」「確認した」「進めて」等を、現在の質問に応じて正しく処理する。
- 電話番号、名前、日時、コース、初回来店、注意事項、最終確認を取り違えない。
- 「確認内容をもう一度」では予約内容を再復唱し、「60分から90分へ変更」等では変更後に空きを再確認して再復唱する。
- 予約状態をFAQや一般説明より優先し、同一質問を無限に繰り返さない。認識できない場合は最大2回まで言い換え、以後は安全に店舗確認へ移行する。
- 低信頼の名前・番号を無確認で保存しない。
- STT、状態判定、DB、TTS、再生開始の遅延を計測し、長い無音の原因を特定できるログを残す。
- 通話履歴を顧客とAIの時系列で保存し、保存失敗・最終状態・ループ理由を管理画面から確認できるようにする。
- 実通話で判明した失敗表現を自動回帰テストに追加し、状態遷移を検証する。
- ローカル検証、本番反映、実電話、予約DB、SMS、通知履歴、電話ログ、店舗ダッシュボードの一致を個別に確認する。

確認していない内容は確認済みと報告しない。コード実装済み、ローカル確認済み、本番確認済み、未確認、要ユーザー対応を分け、実電話と実端末SMSまで確認できるまで完了または提出可能と報告しない。
