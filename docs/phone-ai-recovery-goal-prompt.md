# ARARE AI 電話予約品質改善・本番完了プロンプト

## 目標

ARARE AI の電話予約受付を、店舗オーナーへデモできる本番品質にする。
電話回線と SMS は Twilio を継続利用し、予約内容の理解・状態管理・応答生成には OpenAI/GPT を必要な範囲で利用する。
音声は日本語の落ち着いた男性音声を使用し、外国語話者のような不自然さ、無音、接続失敗、同じ質問の無限反復を起こさない。

## 現在の確認済み基準

- コード上では、予約状態を日時、空き、氏名、電話番号、コース、来店歴、注意事項、最終確認に分離している。
- 本番 Render のヘルスチェックでは、DB、OpenAI、Twilio ConversationRelay、日本語 TTS の設定が有効である。
- 本番 Twilio 番号の着信先は `/api/twilio/voice` に切り替え済みである。
- 現在の音声経路は、Twilio ConversationRelay、Google 日本語音声認識、Amazon Takumi-Neural 日本語男性音声である。
- OpenAI Realtime の経路はロールバック用として残し、合成メディア試験に合格している。
- ローカルの電話回帰試験、署名検証、使用量計測、ビルドは合格している。

上記は実装・設定・自動検証の確認であり、実端末での音質、実 SMS 到達、管理画面反映まで確認済みという意味ではない。

## 今足りていない確認

1. 本番 ConversationRelay で、空き確認から最終確認まで複数ターンが正しく遷移すること。
2. 実電話で日本語男性音声が自然に聞こえ、無音、途中切断、長い待ち時間、発話かぶりがないこと。
3. 「はい大丈夫です」「今のでいい」「了解」「確認した」など自然な肯定を正しく処理すること。
4. 電話番号不一致の確認で、発信番号と読み上げ番号を正しく選べること。
5. 「確認内容をもう一度」で予約内容を再度復唱できること。
6. 「60分から90分に変更」でコース変更後に空きを再確認し、変更済みの内容を復唱できること。
7. 氏名の低信頼認識を勝手に確定せず、確認質問へ進めること。
8. 同じ状態で認識できない回答が続いた場合、最大2回の聞き直し後、安全に店舗確認へ移行すること。
9. 実通話の会話ログが顧客とAIの時系列順で保存されること。
10. 仮予約、予約ID、通話ログ、SMS送信結果、店舗ダッシュボードの表示が同一内容になること。
11. SMSが実端末へ到達し、Twilio上でも delivered まで確認できること。

## 実行指示

1. 現在の本番ルート、Render ヘルス、Twilio 番号設定を取得し、事実として記録する。
2. 回帰用 CallSid を使った本番 WebSocket 試験を実行し、実予約や SMS を作らずに多ターン状態遷移を確認する。
3. 試験が失敗した場合は、失敗した状態、入力、応答、ログを特定し、原因箇所だけを修正する。
4. 修正後は、電話回帰試験、Twilio署名試験、Realtimeメディア試験、ビルドを再実行する。
5. 本番へ反映し、Render のデプロイ完了とヘルスチェックを確認する。
6. 実電話を1本かけ、Twilio CallSid、Renderログ、DB通話ログ、予約、SMS、店舗画面を同一時刻・同一内容で照合する。
7. 音声品質は録音を聞き、日本語らしさ、話速、間、重複、誤認識、無音、切断を評価する。
8. 問題があれば、修正、再デプロイ、再通話、再照合を繰り返す。

## 完了条件

- 本番の日本語ルート多ターン自動試験が全項目合格している。
- 実電話で接続、初回挨拶、認識、応答、割り込み、終了まで異常がない。
- 日本語男性音声が店舗デモに耐える自然さであると実録音で確認できる。
- 予約内容の復唱、訂正、コース変更、電話番号確認が正しい。
- 仮予約が重複なく1件だけ作成される。
- SMSが実端末へ1件だけ届き、Twilioで delivered を確認できる。
- DBの予約、通話ログ、通知ログ、店舗ダッシュボードが一致する。
- 未確認項目が残っていない。

## 報告ルール

- `実装済み`、`ローカル確認済み`、`本番自動確認済み`、`実端末確認済み`、`未確認`を分ける。
- コードを読んだだけの内容を本番確認済みと書かない。
- 外部サービスの反映を確認していない場合は完了としない。
- エラーを握りつぶさず、CallSid、状態、失敗箇所、再発防止策を記録する。
- 全完了条件を満たすまで「完成」「提出可能」と報告しない。
